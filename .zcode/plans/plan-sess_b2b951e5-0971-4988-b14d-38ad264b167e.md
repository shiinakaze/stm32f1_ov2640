## 背景

本次会话完成了 stm32f1_ov2640 项目的 UVC 改造全过程：USB 协议栈接入、UVC 类实现、黑屏根因修复（RM0008 ISO 双缓冲语义）、双帧率/双分辨率描述符、UART/UVC 传输通道宏切换、双语 README 与应用手册。此前生成的 `docs/llm-plan.md` 已被用户删除，现按用户要求以同样内容定位（LLM 交接简报）重新生成，保存到 `.zcode/plans/`。

## 执行步骤

1. 创建 `.zcode/plans/` 目录（Write 工具自动创建父目录，无需额外命令）。
2. 写入 `.zcode/plans/plan.md`，内容为此前 llm-plan.md 的完整交接简报（事实全部来自本会话，无需代码探索），章节结构：
   - **项目定位与当前状态**：UVC 模式 Windows 实测可用；320x240/160x120、30/15fps；实际帧率 10~13 / 15~18fps；`middleware/usb/Projects/STM32F407-UVC/` 为 untracked 参考工程（端点模型不同勿照抄）
   - **构建环境**：Keil MDK / ARMCC AC5 -O1；UV4 命令行命令（`-b`/`-r`，退出码 0 为成功）；`app/main.h` 的 `APP_TRANSPORT` 宏切换；双模式 Flash/RAM 预算表（UVC 15464B、UART 19536B，UART 裕量仅 ~540B 的警告）
   - **代码地图**：app/main.c、stm32f10x_it.c、drivers/ov2640.*、middleware/usb/src|inc（库勿改）、middleware/usb/uvc/ 七个应用层文件各自职责，usbd_uvc.c 标注为核心
   - **硬件事实（违反即坏，共 7 条）**：RM0008 §23.4.4 ISO 强制双缓冲、STAT 只许 DISABLED/VALID（写 NAK 未定义）、CTR_TX 后 DTOG_TX 指向下一缓冲、IN 方向计数裸值直写、PMA 512B 布局（含 BTABLE 死空间复用）、USB 锁死 72MHz、位扫描采集期间必须 NVIC 锁 USB 中断且锁前装好空包
   - **设计不变量（8 条）**：ISO 路径仅由 CTR_TX 驱动（SOF 已从 IMR 移除）、frame_done 在 EOF 包传输完成后置位、feed 写序指针→标志→长度、FID 在装 EOF 包时翻转、SCCB 只在主循环执行、EP1 寄存器仅 USB 中断上下文访问、帧上限 12KB、UART 模式 RAM 裕量约束
   - **已修复缺陷存档（5 条）**：黑屏 v1 根因（单缓冲 ISO + 写 NAK）、SOF 装包的帧内丢包风险改 CTR 驱动、双缓冲改单缓冲腾 RAM、hw_config.h 垫片、类请求码需自定义
   - **可选优化方向**：同地址双缓冲回 368B 包、EP0 缓冲压缩、传感器帧率配置、DHT 注入、UVC 1.1 时间戳
   - **验证清单**：双模式全量构建 0 错 0 警、RAM 对账、烧录后设备管理器/相机应用/属性页档位检查、黑屏排查指引（指向 docs/app-manual.md 第 10 节）
